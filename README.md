# Метеоритный дождь — локальный хост + оверлей

Интерактив для стрима: зрители пишут `!join` в чат Twitch или Kick и появляются на островах. Метеориты выбивают их по одному, последние выжившие побеждают.

Хост — обычный Node-процесс на `127.0.0.1`. **Зависимостей нет**, ставить нечего.

---

## Запуск

```bash
node server/index.mjs        # или: npm start
```

Откроются два адреса:

| | |
|---|---|
| Панель стримера | `http://127.0.0.1:7777/` |
| Оверлей для OBS | `http://127.0.0.1:7777/overlay.html?obs=1` |

В OBS: **Browser Source**, 1920×1080, URL оверлея. Галочка «Shutdown source when not visible» — **снять**, иначе игра перезапустится при переключении сцены.

Посмотреть, как это выглядит, вообще без чата и без настройки:
`http://127.0.0.1:7777/overlay.html?solo=1&bots=300`

## Настройка

**Если вам дали адрес релея** — возьмите `config.streamer.example.json` → `config.json` и впишите два ника: свой на Twitch и канала на Kick. Больше там ничего нет: все остальные настройки берутся из дефолтов, полный их список — в `config.example.json`.

`kick.channel` нужен, когда у вас нет доступа к аккаунту Kick-канала (см. «Если стример не владеет каналом») — тогда чат привязывается по нику, но только на чтение. Если канал ваш или владелец готов нажать кнопку, строку можно удалить и подключить Kick из панели — так бот сможет ещё и писать в чат.

Полный набор опций — в `config.example.json`. Скопируйте его в `config.json` и впишите каналы. Файл в `.gitignore`, секреты из него никогда не уходят в браузер.

```jsonc
{
  "port": 7777,
  "game": {
    "lobbySeconds": 45,    // сколько лобби принимает !join
    "minPlayers": 2,       // отсчёт не идёт, пока не наберётся столько участников
    "winners": 1,          // 1..20
    "autoStart": true,     // стартовать по истечении таймера
    "simulateBots": 0      // >0 — добить лобби ботами (для теста)
  },
  "replies": "minimal",    // off | minimal | verbose — насколько бот болтлив в чате
  "commands": {
    "adminRoles": ["broadcaster", "mod"],
    "islandChoiceRoles": ["everyone"],  // напр. ["sub","vip","mod","broadcaster"] — выбор острова только для сабов
    "joinRoles": ["everyone"]           // кто вообще может играть; тот же список режет ферму альтов
  },
  "allowedHosts": []       // имена, под которыми вы сами открываете панель (напр. LAN-адрес машины с OBS)
}
```

Можно и через переменные окружения: `TWITCH_CHANNEL`, `KICK_CHANNEL`, `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`, `KICK_CLIENT_ID`, `KICK_CLIENT_SECRET`, `PORT`.

### Команды в чате

| Команда | Кто | Что делает |
|---|---|---|
| `!join` | все | на самый свободный остров |
| `!join 1` · `!join 2` · `!join 3` | все (настраивается) | конкретный остров |
| `!meteor start` | модератор | открыть лобби |
| `!meteor go` | модератор | стартовать немедленно |
| `!meteor reset` | модератор | сбросить |
| `!meteor winners N` | модератор | число победителей, 1–20 |

Антиспам: 3 команды / 10 с на зрителя, не больше 40 джойнов в секунду суммарно, повтор того же текста в пределах 2 с игнорируется.

## Что зритель сделать не может

Границы, на которые есть тесты (`tests/anticheat.test.mjs`, `tests/core.test.mjs`):

- **Занять два места.** Личность — это `платформа:числовой-id` из события чата, а не ник: переименование, смена регистра и повторный `!join` ничего не добавляют. Сколько бы раз зритель ни писал `!join N`, он стоит ровно на одном острове, и население островов всегда равно числу живых.
- **Перепрыгнуть с острова, по которому уже летит метеорит.** Вне лобби `!join` не принимается ни хостом, ни оверлеем.
- **Узнать, какой остров тихий, до обратного отсчёта.** Опасность и квоты роллятся из итогового сида, а он появляется только после закрытия набора (см. «Розыгрыш с призами»). До этого их не знает никто, включая хост.
- **Пересадить себя или выпасть из состава через оверлей.** Острова назначает хост; отчёты оверлея на ростер и исход не влияют.
- **Командовать игрой.** `!meteor …` только для ролей из `adminRoles`; саб и VIP получают отказ.
- **Долбить островами.** Переходы упираются в те же 3 команды / 10 с.
- **Достучаться до хоста.** Панель, `/api/*` и `/events` обслуживаются только для своей машины — проверяется заголовок `Host`, а у POST ещё и `Origin`. Это закрывает и ссылку из чата, по которой перешёл стример (иначе страница молча постучалась бы на `127.0.0.1:7777`), и DNS rebinding, и — главное — публичный туннель из раздела про Kick: снаружи остаётся доступен ровно `/webhooks/kick`.

Что остаётся:

- **Альты.** Второй аккаунт на Twitch бесплатен, и по чату он неотличим от второго человека. Если это проблема — `commands.joinRoles`, например `["sub", "vip", "mod", "broadcaster"]`: тогда место в игре стоит денег. Тот же пункт закрывает и одного человека, пришедшего и с Twitch, и с Kick.
- **Привязка чужого канала на релее.** Это не про победу в игре, но соседняя дыра: кто знает адрес релея, может зарегистрировать агента и забрать маршрутизацию чужого канала себе. Нужен инвайт-код — см. «Если стример не владеет каналом».

## Розыгрыш с призами

`"giveaway": { "enabled": true }` в `config.json`. В этом режиме победителя не может выбрать никто, включая стримера, а любой зритель может проверить это сам.

**Как идёт розыгрыш**

1. Лобби как обычно: `!join`, `!join 1-3`. Остров назначает хост.
2. Набор закрывается (таймер или `!meteor go`). Оверлей и чат показывают номер розыгрыша, число участников и хэш состава — с этой секунды состав зафиксирован — и номер раунда [drand](https://drand.love), который выйдет через 3–6 секунд. Его значение пока не знает никто: drand выпускает League of Entropy, раунд подписан их общим ключом.
3. Раунд вышел — сид `sha256("meteor-v1" | № | сид лобби | победителей | хэш состава | randomness)`. Опасность островов, квоты, характеристики и метеориты — всё из него.
4. Хост ведёт матч в реальном времени. Победителя не знает никто, пока его не покажет экран.
5. На экране победителей — номер, хэш состава, раунд drand и сид.

**Что выключено:** тестовые сообщения панели (`/api/chat/inject` → 403) и боты (`simulateBots` принудительно 0) — ими можно было бы вписать в состав кого угодно.

**Журнал** — `draws.jsonl` рядом с хостом, только дописывание: `sealed` (состав), `started` (случайность, сид), `completed` (победители) или `annulled` (сброс посреди розыгрыша, недоступный drand — с причиной). Аннулированный розыгрыш не исчезает, его номер не переиспользуется.

**Проверка.** Панель → «Скопировать запись» даёт JSON розыгрыша; его публикуют для зрителей (Discord, закреп, сайт). `public/verify.html` вместе с `public/js/core.js` и `public/js/draw.js` — статичная страница, её можно выложить на любой хостинг. Зритель вставляет запись, и страница:

- сверяет версию ядра (другое ядро — другой исход при том же сиде);
- пересчитывает хэш состава (сверить с плашкой на записи стрима);
- **сама** берёт раунд у drand и проверяет, что он вышел после закрытия набора;
- пересчитывает сид и прогоняет матч — победители должны совпасть;
- ищет зрителя в составе по нику или id.

**Чего проверка не доказывает:** что в составе нет альтов (состав публичный, подозрительные аккаунты видно) и что засчитан каждый `!join` (сообщение могло упереться в лимит).

**Без сети drand** розыгрыш не стартует: после ~25 секунд повторов он аннулируется, состав сохраняется — `!meteor restart` начинает новый розыгрыш с теми же участниками.

## Twitch

**Чтение работает сразу** — без регистрации приложения, без токенов. Достаточно вписать `twitch.channel`. Хост подключится анонимно по IRC.

Авторизация нужна только чтобы бот **писал** в чат (объявлял победителей):

1. [dev.twitch.tv/console/apps](https://dev.twitch.tv/console/apps) → Register Your Application.
2. OAuth Redirect URL — ровно `http://localhost:7777/auth/twitch/callback`.
3. Client ID и Client Secret → в `config.json`.
4. Откройте `http://127.0.0.1:7777/auth/twitch` (или кнопку «авторизовать» в панели).

После авторизации хост сам переключается с IRC на EventSub — современный транспорт, без риска депрекейта. Принудительно: `twitch.transport` = `"eventsub"` / `"irc"` / `"auto"`.

## Kick

У Kick три транспорта.

### `transport: "relay"` — для раздачи другим стримерам

Стример не заводит приложение, не поднимает туннель и ничего не вписывает кроме адреса релея. Его хост сам дозванивается до релея исходящим HTTPS (работает за NAT, фаерволом и корпоративным прокси), жмёт в панели «Подключить Kick», один раз подтверждает доступ — и всё.

```json
"kick": { "enabled": true, "transport": "relay", "relayUrl": "https://relay.ваш-домен" }
```

#### Если стример не владеет каналом

Бывает, что человек стримит на канале, доступа к аккаунту которого у него нет, и нажать «Подключить Kick» некому. Тогда канал привязывается **по нику**, без чьего-либо согласия:

```json
"kick": { "enabled": true, "transport": "relay", "relayUrl": "...", "channel": "ник-канала" }
```

С заполненным `channel` хост при первом же подключении сам заявляет права на канал; в панели есть и поле «привязать по нику». Работает это на app access token самого релея: Kick разрешает такому токену подписаться на `chat.message.sent` любого канала, если знаешь его `broadcaster_user_id` — проверено живым запросом.

Цена — **только чтение**. Писать в чат можно лишь токеном владельца, поэтому бот объявлять победителей не станет (`/agent/say` ответит 409). Ставьте `"replies": "off"` — победители видны на оверлее. Если владелец позже всё-таки авторизуется, привязка сама повышается до полной.

> Важно: авторизоваться должен именно владелец канала. Если кнопку нажмёт стример со своим личным аккаунтом, Kick привяжет **его** канал, а не тот, на котором он стримит: `broadcaster_user_id` у пользовательского токена берётся из самого токена и переданное значение игнорируется.

> И отдельно: согласия владельца здесь не спрашивают, значит любой, кто знает адрес релея, может привязать чужой канал. Пока круг — свои, это терпимо; при раздаче шире нужен инвайт-код на регистрацию агента и на привязку.

Личность хоста хранится в `.agent.json` — пара id/ключ, которую он генерирует сам при первом запуске. Релей запоминает ключ при первом подключении и потом не пускает с ним никого другого.

Как развернуть сам релей — ниже, в разделе «Релей».

### `transport: "webhook"` — официальный, для себя одного

OAuth 2.1 + PKCE → подписка на `chat.message.sent` → Kick шлёт события на ваш адрес. Каждое событие подписано RSA-ключом Kick и проверяется (плюс защита от повторов и протухших таймстампов). Ничего недокументированного, бот сразу умеет писать в чат.

Цена одна: **Kick должен достучаться до хоста снаружи**, а хост живёт на `127.0.0.1`. Нужен публичный HTTPS-адрес.

1. [kick.com/settings/developer](https://kick.com/settings/developer) → создать приложение.
2. **Redirect URI**: `http://localhost:7777/auth/kick/callback`
3. **Webhook URL**: `<ваш публичный адрес>/webhooks/kick`
4. Client ID / Client Secret и слаг канала → в `config.json`, публичный адрес → в `kick.publicUrl`.
5. Открыть `http://127.0.0.1:7777/auth/kick`.

Разовый туннель для проверки:

```bash
cloudflared tunnel --url http://127.0.0.1:7777 --protocol http2
```

> Туннель ведёт на тот же порт, где живёт панель, поэтому снаружи хост отдаёт только `/webhooks/kick`; на всё остальное с чужим `Host` приходит 403. Без этого адрес туннеля был бы полным пультом управления игрой для любого, кто его узнал. Свои имена (скажем, LAN-адрес машины с OBS) добавляются в `allowedHosts`, публичный адрес туннеля — никогда.

> Обязательно `127.0.0.1`, а не `localhost`: иначе cloudflared пойдёт в IPv6 `::1`, где хост не слушает, и вы получите 502.
> В сетях с корпоративным прокси или фильтрацией quick-туннель может не держать соединение (`Error 1033`, `control stream: client disconnected`) — это ограничение туннеля, не хоста.

### `transport: "ws"` — без публичного адреса, но недокументированный

Читает внутренний сокет Kick. Туннель не нужен, но Kick периодически меняет ключи, и тогда значения приходится подсматривать заново: F12 → Network → фильтр WS → адрес вида `ws-<кластер>.pusher.com/app/<ключ>`, а в его сообщениях `pusher:subscribe` с каналом `chatrooms.<число>.v2`. Это `kick.pusherKey`, `kick.pusherCluster` и `kick.chatroomId`.

Отправка в чат в обоих режимах идёт по официальному API и публичного адреса не требует.

## Релей

Нужен только для Kick и только если игру используют несколько стримеров. Причина одна: Kick шлёт вебхуки **на один адрес, заданный в приложении**. Релей владеет этим приложением, принимает события всех каналов и разводит их по хостам.

```bash
node relay/index.mjs      # или: npm run relay
```

`relay.config.json` (или переменные `RELAY_PORT`, `RELAY_PUBLIC_URL`, `KICK_CLIENT_ID`, `KICK_CLIENT_SECRET`):

```json
{
  "port": 8088,
  "publicUrl": "https://relay.ваш-домен",
  "clientId": "...",
  "clientSecret": "...",
  "sendAs": "bot"
}
```

В приложении Kick прописывается **один раз на всех**:

- Webhook URL: `https://relay.ваш-домен/webhooks/kick`
- Redirect URI: `https://relay.ваш-домен/auth/kick/callback`

Что делает релей и чего не делает:

- проверяет подпись каждого события и отбрасывает повторы — хост получает уже доверенные данные;
- хранит токен каждого стримера у себя, наружу не отдаёт;
- маршрутизирует по `broadcaster_user_id`: событие уходит ровно одному хосту;
- умеет две привязки: по авторизации владельца (чтение + запись) и по нику канала своим app-токеном (только чтение) — вторая для стримеров без доступа к аккаунту канала;
- **не знает про игру ничего** — ни фаз, ни игроков, ни островов. Вся логика остаётся на машине стримера.

Если хост стримера офлайн, событие подтверждается (`200 offline`), а не копится в очереди ретраев: опоздавшее сообщение чата игре всё равно не нужно.

Релей переезжает между площадками сменой `publicUrl` — у стримеров меняется одна строка конфига.

### Docker

Готовые конфиги в `deploy/`, два варианта:

```bash
cd deploy && cp .env.example .env

docker compose -f docker-compose.direct.yml up -d   # есть белый IP: релей + Caddy
docker compose up -d                                # белого IP нет: релей + туннель
```

**На сервере лучше первый.** Снаружи это обычный TLS на 443, неотличимый от любого сайта. Протокол туннеля в некоторых сетях распознают по сигнатуре и рвут соединения — выглядит как бесконечные реконнекты и ошибка 1033, причём MTU и потери пакетов при этом в норме. Второй вариант остаётся для машины без белого IP.

Привязки стримеров живут в томе `relay-data` и переживают пересоздание контейнера; путь к состоянию задаётся через `RELAY_STATE_FILE`. Подробности — `deploy/README.md`.

### Постоянный адрес

Релею нужен **стабильный** домен: он зашит и в приложение Kick, и в сборки стримеров. Одноразовые туннели (`trycloudflare`, `lhr.life`) не подходят — адрес меняется при каждом перезапуске.

С собственным доменом подойдёт именованный туннель Cloudflare: домен делегируется на Cloudflare (бесплатный тариф), затем

```bash
cloudflared tunnel login
cloudflared tunnel create meteor
cloudflared tunnel route dns meteor relay.ваш-домен
cloudflared tunnel run --url http://127.0.0.1:8088 meteor
```

> Всегда `127.0.0.1`, а не `localhost` — иначе туннель пойдёт в IPv6 `::1`, где никто не слушает, и вы получите 502.
> В сетях, где фильтруется трафик к edge-диапазону Cloudflare, туннель рвётся каждые ~40 секунд (`Error 1033`). Проверяется это за минуту: поднимите и подождите.

## Архитектура

```
adapters/twitch.mjs ─┐                        ┌─ outbox.mjs ──> ответы в чат
 EventSub WSS / IRC  ├─> bus.mjs ─> router.mjs┤   (агрегаты, не на каждый !join)
adapters/kick.mjs ───┘   нормализация,        │
 Pusher WSS              дедуп                └─ session.mjs ── сид, ростер, фаза
                                                     │
                                                 hub.mjs (SSE)
                                              ┌──────┴──────┐
                                       overlay.html     control.html
```

**Личность игрока — `platform:userId`**, не ник. Один и тот же ник на Twitch и Kick — два разных игрока; смена ника не теряет историю. Скорость, реакция и внимательность игрока выводятся из ключа и сида матча, то есть заново в каждой игре: постоянных «сильных» и «слабых» аккаунтов нет.

**Матч решает хост, оверлей его рисует.** Хост рассаживает игроков, закрывает набор, выводит сид и сам прогоняет симуляцию с фиксированным шагом `STEP = 1/60` в реальном времени. Оверлей исполняет то же ядро с тем же шагом и поэтому видит тот же матч; его отчёты ни на что не влияют. Перезагруженный оверлей получает параметры матча и номер шага хоста и догоняет его без отрисовки — посреди боя тоже.

**Канал хост → браузер — SSE + POST**, а не WebSocket: трафик низкочастотный, `EventSource` переподключается сам, и серверу не нужна ни одна зависимость.

| Файл | Ответственность |
|---|---|
| `public/js/core.js` | Чистая симуляция. Ни DOM, ни сети — запускается в Node как есть |
| `public/js/render.js` | Канвас, кадровый цикл, таймер лобби, «директор» матча |
| `public/js/net.js` | Транспорт. Про игру не знает ничего |
| `public/js/app.js` | Связывает сеть и рендерер |

## Тесты

```bash
node tests/core.test.mjs    # полный матч вхолостую: детерминизм, личности, победители
node tests/parse.test.mjs   # разбор реальных IRC-строк: ники, права, двоеточия, кириллица
node tests/webhook.test.mjs # приём вебхуков Kick: подпись, подделка, подмена, повтор
node tests/relay.test.mjs   # релей: маршрутизация, изоляция стримеров, привязка, ключи агентов
node tests/relay-e2e.test.mjs # вся цепочка: вебхук → релей → агент → лобби
node tests/draw.test.mjs    # розыгрыш: пересчёт по записи, подделки, частота кадров, сброс, drand
node tests/host.test.mjs    # сквозной путь чат → роутер → оверлей (хост должен быть запущен)

npm test                    # все подряд (хост должен быть запущен)
```

`tests/host.test.mjs` поднимает фальшивый оверлей на SSE и проверяет права, лимиты, дедуп, ресинк и защиту от обхода путей.

Прогнать интерактив без живого чата можно из панели: карточка «Тестовое сообщение» шлёт команды в тот же конвейер, кнопка «случайных !join» набивает лобби.

## Что дальше

- **Лимиты отправки по каналам.** `outbox` сейчас один общий; когда стримеров станет много, пейсинг нужно разводить по каналам.
- **Модерация приложения Kick.** Публичное приложение, которым пользуются посторонние, может требовать их проверки — стоит выяснить до широкой раздачи.
- **Бот в чужом чате.** Возможно, бота придётся делать модератором у каждого стримера, иначе его сообщения попадут под слоумод.
- Иконки платформ у ников в фиде и в таблице победителей.
- Награды за места (сабы, баллы каналов) через EventSub-события.
